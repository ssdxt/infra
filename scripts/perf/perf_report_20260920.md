### 2.3 极限阶梯压测（核心结论）

**GLM 直连阶梯**（每档一轮全并发）：

| 并发 | 成功 | P50 延迟 | max 延迟 | 聚合吞吐 |
|---|---|---|---|---|
| 10 | 10/10 | 1.55s | 1.67s | 122 tok/s |
| **16** | **16/16** | **1.68s** | 2.11s | **173 tok/s ← 峰值** |
| 24 | 24/24 | 2.02s | 3.27s | 161 tok/s |
| 32 | 32/32 | 2.43s | 3.91s | 173 tok/s |

**RAG 全链路阶梯**：

| 并发 | 成功 | P50 延迟 | max 延迟 |
|---|---|---|---|
| 5 | 5/5 | 9.95s | 10.5s |
| 10 | 10/10 | 16.5s | 26.6s |
| 16 | 16/16 | 24.8s | 26.4s |

### 2.4 极限结论

1. **全部 143 个请求 0 失败**——系统在 32 直连并发 / 16 业务并发下没有崩溃点，只有延迟递增。
2. **GLM 有效并发甜点 = 16**（即 maxBatchSize）：16→32 延迟从 1.68s 涨到 2.43s，吞吐不增（172.9→173.1），说明超过 16 后请求在 MindIE 内排队。
3. **RAG 全链路 10 并发延迟 16.5s** 是正常水位：检索+rerank 仅 ~1s，大头是 128 token 生成在 16 batch 内分摊；16 并发时排队延迟 +50%。
4. 业务可承诺容量：**10 并发问答稳定可用（P50 16.5s，max 27.5s）；16 并发可用但变慢；超过 16 建议前置排队/限流**。

## 四、瓶颈分析

1. **算力瓶颈 = GLM 生成**：RAG 16s 延迟中检索+rerank <1.5s，其余为生成；吞吐峰 173 tok/s（双卡 310P3 fp16 的合理水位）。
2. **排队点 = maxBatchSize 16**：>16 并发不失败但延迟线性涨。若业务需要更高并发，加 KV 池（npuMemSize 16→20）+ maxBatchSize 16→24，代价是每卡显存 +4G。
3. **CPU 不是瓶颈**：压测 load 4~10（8核），api 进程仅 321MB。
4. **内存充裕**：压测全程可用 ≥19G。若停掉 speech（6.1G），余量再 +10%。

## 六、上下文长度参数（压测后调整，已验证）

### 6.1 参数现状（`/deploy/models/glm-4-9b-chat/conf/config.json`）

| 参数 | 压测时 | 现值 | 说明 |
|---|---|---|---|
| `maxSeqLen` | 8192 | **32768** | 单请求上下文上限（输入+生成） |
| `maxInputTokenLen` | 8192 | **32768** | 输入上限 |
| `maxPrefillTokens` | 8192 | **32768** | 单批 prefill |
| `maxIterTimes` | 512 | 512 | 单次生成上限（要长回答需另调） |
| `npuMemSize` | 16 | 16 | KV 池/卡——**调上下文不增加启动显存** |
| `maxBatchSize` | 16 | 16 | 并发上限 |

### 6.2 容量数学（KV 池 16G×2卡 ≈ 83.8 万 token 总预算）

GLM-4-9B 每 token KV ≈ 40KB；模型本体上限 `maxPositionEmbeddings=131072`（128K）。

| maxSeqLen 档位 | 满长单请求占池 | 满长并发上限 |
|---|---|---|
| 8192（压测档） | 4% | 16（受 batch 限制） |
| **32768（现档）** | 15.6% | 16 并发全满长占池 62%，安全 |
| 131072（128K 极限） | 62.5% | 满长并发最多 ~6 个 |

### 6.3 32K 实测验证（2026-09-20）

| 项 | 结果 |
|---|---|
| 模型重载 | 35s 就绪 |
| **15,412 token 长输入**（旧配置会被截断） | ✅ 正确处理，摘要准确 |
| 长输入端到端延迟 | 12.5s（15K prefill 合理水位） |
| NPU 显存 | 30.9G/卡（较 8192 档 +2G，32K 位置编码预分配，正常） |
| 剩余显存 | NPU 0 ~7G / NPU 1 ~11G |

> 注意：32K 档下若 16 路并发**全部**塞满 32K 长文会占池 62%，短请求不受影响；如需 128K 档，满长并发上限降到 ~6，且单请求 prefill 时长会到分钟级。
