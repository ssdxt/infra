## 一、结论摘要

该 Atlas 300I Duo 加速卡**无法执行任何 NPU 算子**，包括 `x*2+1` 这样的最小运算。
两颗芯片（Chip 0 / Chip 1）均复现，错误稳定一致，属于**硬件级故障**。

关键异常：**卡的 AICore 在访存时报「DDR 地址越界」并伴随「MTE CCU ECC 错误」，
但 `npu-smi` 自检显示 Health=OK、Chip Fault=0、DDR ECC 计数器全为 0 —— 自检结果与
实际运行状态矛盾，驱动层未能正确上报该硬件故障。**

已排除软件侧全部可能：更换 2 个驱动版本、3 个 CANN 版本、设备复位、
两颗芯片分别测试、宿主机直跑与容器内跑,均为同一错误。**申请检测并更换该卡。**

## 三、故障现象

### 3.1 最小复现：单算子 `x*2+1`

任意 NPU 算子执行即失败，两颗芯片表现一致：

```python
import torch, torch_npu
torch.npu.set_device(0)
x = torch.tensor([1.0, 2.0, 3.0], dtype=torch.float16).npu()
y = (x * 2 + 1).cpu()
```

**Chip 0 输出：**

```
errorStr: The DDR address of the MTE instruction is out of range.
aicore int: 0x10
mte ccu ecc 1bit error: 0x3280000000000000
coreId( 0):        0x800000
Kernel task happen error, retCode=0x26, [aicore exception].
fault kernel_name=0/1_-1_0_Mul1_tvmbin
```

**Chip 1 输出：**

```
errorStr: The DDR address of the MTE instruction is out of range.
mte ccu ecc 1bit error: 0xf80000000000000
coreId( 0):        0x800000
Kernel task happen error, retCode=0x26, [aicore exception].
```

> 注意：崩的是 `Mul1`（乘法）算子，`x*2+1` 三个 f16 元素。

## 五、需要厂商重点关注的疑点

### 疑点 1：自检全绿，但实际不可用（驱动上报缺失）

```
$ npu-smi info
| 24  310P3  | Health: OK |
| 0   0      | 0000:0B:00.0 |
| 24  310P3  | Health: OK |
| 1   1      | 0000:0B:00.0 |

$ npu-smi info -t health -i 24 -c 0
  Health Status                  : OK
  Error Code                     : NA
  Error Information              : NA

$ npu-smi info -t board -i 24
  Chip Fault                     : 0

$ npu-smi info -t ecc -i 24 -c 0     （chip 1 同样）
  DDR Single Bit Error Count               : 0
  DDR Double Bit Error Count               : 0
  DDR Single Bit Aggregate Total Err Cnt   : 0
  DDR Double Bit Aggregate Total Err Cnt   : 0
  DDR Single Bit Isolated Pages Count      : 0
  DDR Double Bit Isolated Pages Count      : 0
```

**而同一时刻 AICore 报 `mte ccu ecc 1bit error`。**
`Health=OK` / `Chip Fault=0` / ECC 全 0 与运行态矛盾，**运维监控无法据此发现该故障**，
请协助确认是卡内 ECC 上报通路异常，还是 AICore 侧状态异常。

### 疑点 2：PCIe 链路降速

```
LnkCap: Speed 16GT/s, Width x16
LnkSta: Speed 16GT/s (ok), Width x8 (downgraded)
```

预期 x16，实际 x8。请确认是否与卡体 / 金手指 / 插槽接触相关。

### 疑点 3：显存疑似存在残留占用

复位前后 `npu-smi info` 均显示如下，且进程列表为空：

```
| 0 | 0 | ... | 1642 / 44280   (MB) |
| 1 | 1 | ... | 1290 / 43693   (MB) |
| No running processes found in NPU 24 |
```

无进程却占用约 1.6 GB / 1.3 GB 显存，请确认是否为异常残留。

## 六、复现步骤（供厂商复现）

```bash
# 1. 环境确认
npu-smi info -t board -i 24          # 核对序列号 2106030737ZER3013372

# 2. 最小复现（宿主机，需已安装 torch_npu）
cat > /tmp/t.py <<'EOF'
import sys
import torch, torch_npu
dev = int(sys.argv[1])
torch.npu.set_device(dev)
print(f">>> device {dev} set_device OK", flush=True)
x = torch.tensor([1.0, 2.0, 3.0], dtype=torch.float16).npu()
y = (x * 2 + 1).cpu()
print(f">>> device {dev} RESULT OK ->", y.tolist(), flush=True)
EOF

export ASCEND_GLOBAL_LOG_LEVEL=3
python3 /tmp/t.py 0    # Chip 0
python3 /tmp/t.py 1    # Chip 1
```

**预期结果**：打印 `RESULT OK -> [3.0, 5.0, 7.0]`
**实际结果**：报 `aicore exception`，`errorStr: The DDR address of the MTE instruction is out of range`
