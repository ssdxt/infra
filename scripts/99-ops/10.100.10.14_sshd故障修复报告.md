# 10.100.10.14 sshd / SFTP 故障修复报告

- 时间：2026-09-22 16:17–16:19
- 操作人：DSH 排障代理（经用户确认后执行）
- 主机：吴兴区工业智能体公共底座-控制面节点2（10.100.10.14，ubuntu 22.04）

## 1. 故障现象

1. `sshd -t` 失败：`OpenSSL version mismatch. Built against 30000020, you have 30400000`（rc=255）
2. SFTP 无法传输：客户端连接后立即 `Connection closed`
3. `systemctl restart ssh` 失败（unit 的 `ExecStartPre=/usr/sbin/sshd -t` 即失败，restart counter=7）
4. shell 登录正常（依赖一个 9/19 启动的旧进程）

## 2. 根因

`/etc/ld.so.conf.d/openssl.conf` 将 `/usr/local/openssl/lib64`（手工编译的 OpenSSL 3.4.0，2024-11 前后安装）置于动态库搜索优先级最高，**遮蔽系统 OpenSSL 3.0.2**。

- 磁盘上的发行版 openssh（8.9p1-3ubuntu0.17，按 OpenSSL 3.0 编译）每次被 exec 时都加载到 3.4.0，OpenSSH 对 OpenSSL 小版本不一致执行硬退出 → `sshd -t`、sftp-server（每个 SFTP 会话都新 exec 一次）、服务重启全部即死。
- 端口 22 之所以还活着：9/19 启动的手工安装上游 OpenSSH 10.2 监听进程（按 3.4.0 编译，banner 为裸 `OpenSSH_10.2`）仍在内存中运行；此后 apt 将磁盘二进制换回发行版 8.9（该进程 exe 呈 `deleted` 状态）。shell 会话由旧进程 fork 而来、不 exec 新二进制，因此幸存。
- 另：`/run/sshd` 目录随 unit 失败被清理，修复时一并重建。

## 3. 修复过程（分阶段、可回滚，全程留痕 /root/fix_openssl_shadow_20260922.log）

| 阶段 | 动作 | 结果 |
|---|---|---|
| 1 | `LD_LIBRARY_PATH=/lib/x86_64-linux-gnu sshd -t` 干跑验证（不动任何配置） | OK（仅暴露 /run/sshd 缺失，属正常） |
| 2 | `openssl.conf` 改名为 `openssl.conf.disabled-by-dsh-20260922` + `ldconfig` | libcrypto 解析回落系统 3.0.2 |
| 3 | 真实 `sshd -t`（失败则自动回滚上一行） | OK |
| 4 | 先在 2222 端口拉起救援 sshd 验证修复后状态 | OK |
| 5 | 确认 pid 813 身份后 kill，`systemctl reset-failed ssh && systemctl start ssh` | 新发行版 sshd pid 161302 监听 22 |
| 6 | 关闭 2222 救援进程 | OK |

## 4. 回归验证（全部通过）

- `sshd -t` rc=0；`systemctl is-active ssh` = active、enabled
- banner：`SSH-2.0-OpenSSH_8.9p1 Ubuntu-3ubuntu0.17`（回到发行版一致状态）
- `openssl version` 自洽：`3.0.2 (Library: 3.0.2)`
- SFTP 上传往返成功（原始故障场景复现通过），测试文件已清理

## 5. 回滚方式

`mv /etc/ld.so.conf.d/openssl.conf.disabled-by-dsh-20260922 /etc/ld.so.conf.d/openssl.conf && ldconfig`（备份同时存于 `/root/openssl.conf.backup-20260922`）。`/usr/local/openssl` 目录本体未做任何删改。

## 6. 遗留风险与建议

1. **全集群 14 台机器 22 端口 banner 均为手工安装的上游 OpenSSH 10.2**。本次已核验 .10/.19 为 `sshd -t` rc=0、服务 active（自洽可用），但整批机器存在"手工二进制 + apt 混管"漂移风险（.14 就是这么炸的）。建议与装机负责人确认 10.2 的来源与维护策略，统一收敛为发行版包或统一的自建版本。
2. .14 现已与发行版完全一致，unattended-upgrades 后续升级安全。
3. Excel 清单中"请确认数据盘挂载是否可以"等全量核验尚未执行（被本故障打断），可另行安排。
