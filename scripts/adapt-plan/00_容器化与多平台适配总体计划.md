# 容器化与多平台适配总体计划

> 依据：本地备份 `D:\ssdxt\西安\deploy`（omniknow-1.0，西安项目，源机 192.168.21.111 已下线）。
> 本文档为规划基线，所有"现状"均从备份文件核实，标注 ✅ 已核实 / ⚠️ 待验证。

## 一、目标

1. **配置去 IP 化**：所有服务间调用不再写死宿主 IP，做到"改一个 .env / values 文件即可换环境"。
2. **全员容器化**：api / web / speech 三个 systemd 裸进程进容器，与已有的模型/OB/nginx 容器统一编排（docker-compose 自定义网桥 + DNS 服务发现）。
3. **统一入口**：外部经 **WAF → nginx**（或 k8s **Gateway API**）代理，外部地址与内部地址解耦。
4. **k8s 就绪**：给出 k8s 形态方案（含昇腾 NPU 调度、otel 可观测性），作为二期目标。

## 三、目标形态

### 形态 A：docker-compose 全容器 + nginx + WAF（一期，推荐先落地）
- 单机自定义网桥 `app-net`（如 172.30.0.0/24），全部服务名互访（DNS），OB 保持独立网桥固定 IP。
- nginx 为唯一入口（80/443），静态 web + `/api`→api + `/voice`→speech 反代；WAF 挂 nginx 前面。
- 所有可变参数收敛到 **一份 `.env`**（compose 自动注入 + 容器内 `os.getenv` 兜底）。

### 形态 B：k8s + Gateway API + otel（二期）
- 应用 Deployment（api/web/speech）、模型独立节点池（昇腾 device plugin + volcano 整卡调度）、OB 留在 VM/裸机或单实例 StatefulSet（元数据绑 IP 风险见 03 文档）。
- Gateway API 统一南北向；otel 全链路（详见《03_SRE 补充》）。

## 四、阶段计划

### P0 配置外部化（不动架构，0.5~1 天）
| # | 动作 | 产出 |
|---|---|---|
| 1 | `configs/*.py` 全部可变项改 `os.getenv(...)` 带默认值 | 代码 patch |
| 2 | 建 `.env` 模板（DB/模型/密钥/外部URL 一处收敛） | `.env.example` |
| 3 | `index.html` 去 IP（三方案见 02 文档，推荐 nginx 相对路径方案，P2 一起做则先行子_filter 过渡） | 模板化 index.html |
| 4 | 死地址清理（utils.py:746、tools_api 5.210 等，改为 env 可配+默认关闭） | patch |
- **退出标准**：原机形态（裸进程）下仅改 `.env` + 重启，登录/问答/文档上传冒烟全过。

### P1 全容器化 + 自定义网桥（2~3 天）
| # | 动作 | 要点 |
|---|---|---|
| 1 | api 镜像 | 基于 `tar/recovery.tar`（conda pack 1.9G）制镜像；含 LibreOffice/ffmpeg 依赖则装进镜像 |
| 2 | web 镜像 | nginx 直接伺服静态文件（废弃 https_server.py，TLS 交给入口） |
| 3 | speech 镜像 | 基于 `tar/melo_tts.tar`；昇腾设备挂载同 embed 容器写法；备选 `code/melott/Dockerfile`（python3.9 路线，端口 8888，需适配 seaco 入口） |
| 4 | compose 总编排 | `app-net` 自定义网桥；OB/embed/rerank/glm 从 host 网络迁入 bridge（端口冲突重排：见 02 端口表）；模型容器保留设备挂载 |
| 5 | 健康检查与依赖序 | healthcheck + depends_on(condition)；错峰启动（防加载风暴——源机曾因 5 容器同时自启压死 sshd） |
- **退出标准**：`docker compose up -d` 一条命令拉起全栈；冒烟 + 10 并发 RAG 压测 P50 ≤ 20s（对齐源机基线 16.5s）。

### P2 nginx + WAF 统一入口（1~2 天）
| # | 动作 | 要点 |
|---|---|---|
| 1 | nginx 业务 server 段 | `/`→web 静态、`/api/`→api:8261、`/voice/`→speech:7870；SSE 流式必须 `proxy_buffering off`（RAG P50 16.5s） |
| 2 | 前端相对路径 | `base_api=''`（同源），voice 同理；一次改造永久免 IP |
| 3 | WAF 接入 | 外部域名→WAF→nginx；透传 `X-Forwarded-For/Proto`；uvicorn 侧开 `--proxy-headers` 并限制 `forwarded-allow-ips` |
| 4 | 生产加固 | `/docs`、`/redoc` 在 WAF/nginx 层封禁；上传 `client_max_body_size`（文档/音频）；TLS 证书替换自签 |
- **退出标准**：外部走域名/WAF 全功能可用，内外地址不同不影响任何配置。

### P3 k8s + otel（3~5 天，二期）
清单见《03_SRE 补充》：昇腾 device plugin、整卡调度、探针/PDB、otel Collector、Gateway API、监控告警迁移。
- **退出标准**：k8s 上全栈冒烟 + otel 链路（一次 RAG 请求的 trace 完整贯穿 api→embed/rerank→glm）。

## 五、风险登记

| 风险 | 等级 | 缓解 |
|---|---|---|
| OB 元数据绑容器 IP：换网段/换平台=集群重建 | 高 | 迁移前 mysqldump 业务库；新环境全新初始化+导数据；k8s 形态建议 DB 不进集群 |
| 模型容器 host→bridge 网络迁移（MindIE/TEI 对监听地址敏感） | 高 | 已验证 embed/rerank 可 `0.0.0.0` 监听（源机改过）；MindIE config `ipAddress` 改 0.0.0.0 需回归 |
| 多容器同时自启→加载风暴（源机实证压死系统） | 高 | compose `depends_on` + restart: on-failure + 错峰 delay；k8s initContainer/PDB |
| npu-exporter 容器内 DCMI 不可见（15+ 组合验证失败） | 中 | 保持宿主 systemd 直跑；k8s 用 DaemonSet hostNetwork + hostPath 驱动 |
| arm64 单架构镜像，"适配不同平台"受限 | 中 | multi-arch 构建；昇腾栈仅 arm64 可用，k8s 用 nodeSelector 隔离 |
| 前端缓存旧 index.html | 低 | 文件名加 hash / nginx no-cache index.html |
| 死地址功能（18001/7890/7863/9000/8002）调用即 500 | 低 | P0 一并 env 化默认禁用，避免验收期踩雷 |
