# 交付文档编写规范

## 原则
面向"照着做能跑通"的读者：可复现、可定位、少歧义。用中文、直白语言。

## 结构模板
1. **概述**：本文档适用系统/组件、读者对象、前置条件。
2. **环境要求**：OS、版本、资源、端口、依赖清单（含确切断言版本）。
3. **安装/部署步骤**：
   - 编号步骤，每步给命令与预期结果；
   - 命令可复制；关键参数给示例；
   - 标注易错点与常见失败表现。
4. **验证清单**：如何确认部署成功（健康检查/冒烟）。
5. **操作说明**：日常启动、停止、升级、配置修改。
6. **排障指南**：症状→可能原因→排查命令→解法（沉淀自 troubleshoot）。
7. **附录**：版本历史、变更记录、联系方式。

## 写作注意
- 先写清晰结论/摘要，再给细节；
- 用真实命令与输出，不编造；
- 注明"已验证"与"待验证"内容，不夸大；
- 时间、版本、路径等具体信息准确。

## 边界
- 不复制未经验证的外部操作步骤当结论。
- 涉及客户环境的敏感信息先做脱敏处理。
