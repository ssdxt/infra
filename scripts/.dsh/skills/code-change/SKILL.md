# 代码/配置修改规范

## 目的
在改动任何代码、配置或脚本前建立最小风险路径，确保改动可控、可追溯、不破坏无关功能。

## 步骤
1. **先读后改**：修改前必须读取目标文件及其上下文（相关调用方、被调用方、同目录兄弟文件），不得在未读的情况下断言文件内容。
2. **明确意图**：一句话说明"这次要达成什么"，以及"不该影响什么"。
3. **最小改动**：只改达成目标所需的差异；用 edit 做精准替换，避免整文件重写引入无关变动。
4. **格式校验**：YAML/JSON 类文件在改动后校验语法（对齐、缩进、引号）；脚本检查括号/引号配平。
5. **改后自检**：
   - 重新读改动区，确认语义正确；
   - 确认没有破坏相邻行或格式；
   - 若被观测策略约束，遵循文件观测规则。
6. **不擅自扩大范围**：发现问题超出当前意图时，先提出，不顺手改一堆。

## 边界
- 不确定文件归属/影响面时，先读取或询问，不凭记忆猜测。
- 删除文件或目录前先列出将删除的内容再执行。
