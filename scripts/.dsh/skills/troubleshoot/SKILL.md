# 故障排查方法

## 核心原则
证据优先、最小复现、单一变量、改一处验一处。不要凭猜测连改多处。

## 流程
1. **复现与界定**：拿到完整报错原文（不只摘要）；确认触发条件、是否稳定复现、影响范围。
2. **收集证据**：按序收集日志/状态——
   - 服务/进程状态（systemctl、ps、docker ps、进程端口）；
   - 应用日志尾部与报错点上下文；
   - 系统信息（OS、内核、驱动、磁盘、内存、时间同步）；
   - 配置与版本（部署清单、镜像 tag、配置文件）。
3. **定位**：
   - 沿调用链/依赖自下而上或自上而下缩小范围；
   - 用二分法隔离：禁用/替换单一环节验证；
   - 区分：环境问题 vs 配置问题 vs 应用 bug vs 版本不兼容。
4. **假设-验证**：每个假设对应一个最小试验，记录结果；被推翻就换假设，不恋战。
5. **修复与验证**：应用修复后做回归，确认原症状消失且无新症状。
6. **沉淀**：把根因与解法记入交付/排障文档（见 delivery-doc），供后续复用。

## 常见快速检查
- 端口/监听：`ss -tlnp` / `netstat -tlnp`
- 磁盘满：`df -h`
- 资源占用：`free -h`、`nproc`、`ulimit -n`
- 时间同步异常导致认证/证书失败：`date`、`timedatectl`
- 容器：`docker ps -a`、`docker logs <id>`

## 边界
- 不要把"没验证过的猜测"当成结论输出。
- 远程服务器操作注意权限与安全；破坏性命令先确认。
